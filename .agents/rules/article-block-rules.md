# Block-First Article Authoring Rules (ブロックファースト記事作成原則)

誰が（人間）作っても、どのAI（Claude, Cursor, Antigravity, Windsurf等）が作っても、後から管理画面（Admin UI）で手動で直接手直し・加筆・修正ができるよう、記事コンテンツは以下の構造化ブロックを基本単位として作成・更新しなければならない。

---

## 1. 基本方針（手動編集性の担保）
- **生HTML（Raw HTML）の直打ち禁止**:
  - `CustomHtmlBlock` に巨大なHTML（テーブルタグ、カードレイアウト、CTAタグ等）を丸ごと流し込む作成方法は**原則禁止**。
  - 生HTMLで作成されたコンテンツは管理画面でビジュアル編集できず、人間による手動メンテが不可能になるため。
- **標準ブロックコンポーネントの使用**:
  - EmDash管理画面のブロック追加メニュー（Turn into / Insert block）から直接操作・入力できるブロック群を用いて構築する。

---

## 2. 要素別・標準ブロックの使い分け規則

| 要素種別 | 推奨ブロック種別 | 目的・手動編集のメリット |
| :--- | :--- | :--- |
| **見出し・本文** | 標準段落 (`h2`, `h3`, `normal`) | 管理画面上でテキストの打ち替え、フォントスタイル変更が即座に可能 |
| **注釈・補足** | `notes` または 段落スタイル `note` | 12.5px・行間1.45の注釈スタイルとして管理画面上で直接加筆・修正可能 |
| **比較表・スペック・価格一覧** | `table` (TableBlock) | 管理画面のテーブルエディタでセルの値・行・列を個別に手動編集可能 |
| **CTA（コンバージョンボタン）** | `cta` (CTABlock) | ボタン文言、遷移先URL、直下の補足注記（subtitle）を個別に変更可能 |
| **メリット・特徴・カード** | `columnCards` / `benefitCards3Col` | 各カードのタイトル、説明文、アイコン、バッジを個別に手動編集可能 |
| **Q&A・よくある質問** | `accordion` / `faq` | 質問と回答のアコーディオンを開閉しながら直感的に加筆・修正可能 |
| **左右分割（写真＋解説）** | `split_media` (SplitMediaBlock) | 写真と解説が1対1で対応する重要な装備差・特徴説明用 |
| **ギャラリー・写真スライダー** | `slider` (SliderBlock) | 画像の追加・差し替え・キャプション修正が管理画面から可能 |

---

## 3. 写真前提の解説と「No Image」プレースホルダー原則
- **写真があって成立する説明のレイアウト**:
  - ヘッドライト形状、ディスプレイ・コックピット、シート素材、ホイールデザインなど、「写真を見て初めて理解できる解説」は、写真配置を前提としたレイアウト（`split_media` や画像付きカード等）で構築する。
- **実写真がない場合の対応**:
  - 執筆・自動生成時点で適切な実写真が存在しない場合でも、テキストのみの単調な箇条書きに逃げず、**必ず標準プレースホルダー画像（`/images/no-image.svg`）をセットしてブロックを完成させる**こと。
  - これにより、読者や人間編集者が「ここに写真が入るべき構造」であることをひと目で把握でき、後から管理画面のメディアピッカーで実写真に差し替えるための確実な目安（目印）となる。

---

## 4. スクリプト・プログラムによるデータ投入時の規則
AIがスクリプト（`scripts/` 等）で記事データを一括生成・投入・修正する場合も、必ず上記ブロックのスキーマ（JSONオブジェクト構造）に従ってリビジョン（`live`, `draft`）を生成すること。
- `table` ブロックにはヘッダー配列と行データ配列を正規のJSON構造で格納する。
- `cta` ブロックには `label`, `url`, `buttonStyle`, `buttonShape`, `subtitle` を個別のプロパティとして格納する。
- 投入後は必ず全リビジョンの同期と `npm run db:backup` を行い、手動編集画面で正常に開けることを確認する。

---

## 5. エディタ設定・装飾の完全描画保証原則（Editor-Render Parity Rule）
管理画面（Admin UI）のエディタ上でユーザー・編集者が設定できるすべてのスタイルや機能は、Webサイト側で100%確実に反映されなければならない。
- **文字配置（Text Align）の完全透過**:
  - 段落（`<p>`）、見出し（`h1`〜`h6`）、注釈（`note`）、引用（`blockquote`）、リスト項目（`li`）など、すべての基本要素で `node.textAlign`（`left`, `center`, `right`, `justify`）を拾い、インラインスタイル（`style="text-align: ..."`）およびCSSクラス（`.has-text-align-*`）へ確実に変換して出力すること。
  - スタイルが CSS（`.prose` やデフォルトリセット）で上書きされて無効化されないよう、最優先（`!important`）で適用を担保すること。
- **リンク属性（新しいタブで開く）の完全反映**:
  - エディタで「新しいタブで開く（Open in new tab / `blank: true`）」が指定されたリンクは、確実に `target="_blank" rel="noopener noreferrer"` を出力すること（ページ内アンカー `#...` は除く）。

---

## 6. 見出しスマートアンカーとリンクの大文字・小文字表記揺れ自動吸収原則（Smart Anchor & Case-Insensitive Jump Rule）
- **スマートアンカー記法のサポート**:
  - 見出し（H2〜H4等）の末尾に `[#anchor-name]`、`{#anchor-name}`、または全角 `［#○○］` を記述することで、画面表示からタグ文字を自然に除去しつつ、自動で `id="anchor-name"` を要素に付与する。
  - ヘッダー固定ナビゲーションに隠れないよう、全アンカー要素に `scroll-margin-top: 95px !important;` を適用する。
- **大文字・小文字・全角の表記揺れ自動吸収**:
  - HTMLのアンカー仕様はCase-Sensitive（大文字小文字を区別）だが、編集者が `#FAQ` と書いても見出しが `[#faq]` であったり、その逆であっても**100%確実にジャンプする二重フォールバック**を担保すること：
    1. 見出しコンポーネント側で大文字・小文字両方のエイリアスID（`<span id="...">`）を自動生成。
    2. ページ内クリック時に大文字・小文字を無視して対象要素を探し、スムーズスクロールするクライアントスクリプトを設置。

---

## 7. 管理画面内の案内・注釈表記の直感性原則（Intuitive In-Editor Guidance Rule）
- 管理画面のリピーターやカルーセル内の「ボタンリンクURL」等の注釈には、内部実装の識別子（例: `#cmp-booking` 等の謎の英字）をそのまま並べず、ユーザー・編集者が直感的に意味を理解できる日本語の注記（例: `※他ページへのリンク（例: /locations や /contact）のほか、見出し末尾に [#○○] と入れた場所へ「#○○」で直接ジャンプできます。`）を必ず配置すること。
- モーダル内のリピーター項目（左右分割ブロックやカルーセル項目など）は初期状態で折りたたみ、見出しタイトルを太字・バッジで強調して俯瞰性を担保すること。
